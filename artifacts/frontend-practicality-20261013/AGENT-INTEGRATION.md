# Muse / Dot 接入评估（2026-10-13）

用户明确指 Meta Muse 和 OpenAI Dot。本次完成可行性研究，未连接账号、同步行程、开放接口或创建自动任务。

## 可行路径

| 产品 | 官方支持 | Jacob Travel 的适配方式 |
| --- | --- | --- |
| Meta Muse | Connector 指南接受有权限范围与认证的 API / MCP。公开上架需要产品、安全等审核 | 以已有旅行系统为服务，提供有认证的只读 API / MCP，再适配 Muse connector；批准与账号可用性需单独确认 |
| OpenAI Dot | 可使用账号已启用且有权限的插件；也能单独授权连接本机。云浏览器与本机浏览器会话分离 | 共享同一组只读 MCP tools，封装为支持的插件；或先授权 Dot 访问本机现有界面。不是把 Dot 当作普通 API 聊天模型直接嵌入 |

依据：[Muse 连接器指南](https://muse.ai/platform/docs)、[Dot 官方说明](https://learn.chatgpt.com/docs/dots)。官方文档支持这些通道，但未验证用户账号已能启用相应产品，也未取得任何第三方接入审核。

## 当前系统缺口

行程调整、订单/待办状态、收藏、备注与支出主要保存在本机浏览器；文件资料保存在 IndexedDB。现有 `api/travel-app.mjs` 是页面服务，并非业务 API。云端代理打开生产网址看到的默认数据，不等于用户浏览器中的最新行程。现有完整备份可能含私人备注、自定义项等，不适合作为默认代理输入。

## 建议首版：只读旅行助理

1. 本机界面先显示并让用户选择可分享摘要：日期、城市、当天正式安排、已有时间、准备状态和返回系统的深链。默认排除私人备注、订单号、证件/票据文件、私人入住链接、实际位置；酒店地址与预算由用户选择。
2. 若需要跨设备持续读取，再明确授权摘要同步。服务端提供 `read_trip_summary`、`read_day`、`read_readiness`，包含数据版本和最后同步时间；认证按用户隔离、只读 scope 可撤销，密钥留服务端。
3. 同一只读服务供 Muse connector 和 Dot plugin 使用。先验证读 D2/D18、日期/状态一致、过期摘要提示、撤销后拒绝访问、跨用户访问拒绝，才考虑扩大范围。
4. 若以后需要 AI 改行程，返回建议供界面预览；用户明确确认后才能应用，使用现有撤销和版本冲突检查。这不属于本次实现。

新私有端点必须返回 `Cache-Control: no-store`，并在 service worker 中排除：当前 `public/sw.js` 会处理同源 GET，不能让私人摘要落入通用离线缓存。不得把摘要放在公开 `public/` 静态目录。

首版用途可为“今天去哪、有哪些未准备事项、某项安排在哪里”。监控、消息发送、订票和后台持续任务均需分别授权；已取消的 Jacob Travel 定时任务不会因研究 Dot 恢复。

## 实施前需要确定

选择 Muse 或 Dot 首个验证对象、账号实际可用性，以及是否允许选定摘要离开本机。没有这些信息时先保留这份方案，继续已有前端优化。
